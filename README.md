# fomoxa-go

Fomoxa in Go, written from the specification: the runtime that carries Fomoxa
messages over TCP or UDP — framing, schema handshake, heartbeat, and a tick loop
that never blocks.

No dependencies beyond the standard library. No goroutines. No `context`. No
engine.

```
go get github.com/fomoxa/go
```

## What this is, and what it answers to

The [protocol specification](https://github.com/fomoxa-protocol/protocol-specification)
is the authority here, and nothing else is:

| Document | What it fixes |
|---|---|
| RFC-0001 | What Fomoxa is, and the five design decisions behind it |
| RFC-0002 | The byte layout: primitives, string, bytes, model, array, enum, version differences |
| RFC-0003 | Conformance: the test vectors an implementation must pass, all of them |
| [Implementation guide](https://github.com/fomoxa-protocol/protocol-implementation-guide) | The layer above: framing, handshake, heartbeat, the transport contract |

Where this package and any other Fomoxa SDK disagree, the RFCs decide, and both
sides agreeing with each other proves nothing.

This package is one layer of three, and only one:

```
  your application
        |
  codec         RFC-0002 — Model <-> bytes                 generated by fomoxac,
                                                           NOT in this repository
        |
  runtime       implementation guide — frames, handshake,  frame.go, session.go,
  (this package) heartbeat, tick loop, events              conn.go, server.go
        |
  transport     TCP or UDP, or one you write yourself      transport.go, transports_unix.go
```

A message payload is opaque here, from the transport all the way up to the event
handed to your application. Nothing in this repository reads a byte of it, and
nothing in it encodes or decodes a Fomoxa model — that is `fomoxac`'s generated
output, and a second copy of it in a second place is how two encoders in one
language start to drift.

## Quick start

### Client

```go
conn, err := fomoxa.DialTCP("127.0.0.1:7788", schema, fomoxa.DefaultConfig())
if err != nil {
    return err
}
defer conn.Close()

for now := range ticker.C {
    for _, event := range conn.Tick(now) {
        switch event.Kind {
        case fomoxa.EventReady:
            // only now may you send
        case fomoxa.EventMessage:
            handle(event.MessageID, event.Payload)
        case fomoxa.EventHandshakeFailed, fomoxa.EventDisconnected:
            return event.Err
        }
    }

    if conn.State() == fomoxa.StateReady {
        _ = conn.Send(messageID, payload)
    }
}
```

### Server

```go
server, err := fomoxa.ListenTCP("127.0.0.1:7788", schema, fomoxa.DefaultConfig())
if err != nil {
    return err
}
defer server.Close()

for now := range ticker.C {
    for _, event := range server.Tick(now) {
        switch event.Kind {
        case fomoxa.EventMessage:
            _ = server.Send(event.Peer, replyID, event.Payload)
        }
    }
}
```

`examples/echo-server` and `examples/echo-client` are the same thing, running:

```
go run ./examples/echo-server -network udp
go run ./examples/echo-client -network udp
```

## The schema you hand it

The transport layer never computes a fingerprint; it only compares. Your
application supplies, per message, the triple the handshake needs: the message
id, its field count, and its prefix fingerprint chain — entry `k-1` covering the
first `k` fields, the last entry being the message's own fingerprint.

`fomoxac` generates exactly that table for Go, as `FomoxaMessages` in the
generated `handshake.go`. Mapping it across is mechanical:

```go
messages := make([]fomoxa.Message, 0, len(generated.FomoxaMessages))
for _, m := range generated.FomoxaMessages {
    messages = append(messages, fomoxa.Message{
        ID:          m.ID,
        Fingerprint: m.Fingerprint,
        Prefixes:    m.Prefixes,
    })
}
schema, err := fomoxa.NewSchema(generated.FomoxaSchemaFingerprint, messages)
```

The prefix chain is what makes RFC-0002 §9.1 answerable on the wire. A single
fingerprint per message cannot answer it: hash `Item{id, name}` and
`Item{id, name, hp}` and the prefix relation between them is gone. The chain
commits to each prefix separately, so the two ends can compare at
`k = min(their field count, ours)` — which is §9.1's "the shorter type sequence
must be an exact prefix of the longer one", written as one comparison.

Two peers whose schemas differ still connect, as long as every message both ends
declare agrees on the fields both ends carry. Appending a field at the end of a
message is not a conflict; RFC-0003 §8.6 vectors V-001 and V-002 say such a pair
**must not** be rejected, and `TestAppendingAFieldAtTheEndMustInteroperate`
holds this package to it.

## The rules this package keeps

| | |
|---|---|
| **Nothing blocks.** | Every operation reports the state at the moment it was asked and returns. Sockets are read and written through `syscall.RawConn` with the callback returning `true`, so no call ever waits for readiness. |
| **No goroutines.** | Your loop drives everything. The package starts no threads of execution, so there is nothing to synchronise and no hidden concurrency to reason about. |
| **Time is a parameter.** | `Tick(now)` takes the instant; nothing reads a clock internally. A whole expiry cycle runs in a test in microseconds. Pass `time.Now()`, whose monotonic reading is what `Sub` uses — never a wall-clock time reconstructed from a timestamp. |
| **Wire order is absolute.** | While a frame is still waiting to go out, no other frame may pass it. A send made in that window is refused with `ErrCongested` rather than queued, so a peer that stops reading shows up as an error instead of as memory growth. |
| **The handshake gates the application.** | `Send` before `EventReady` returns `ErrNotReady`, and no application byte reaches the wire before both ends agree they read bytes the same way. |
| **Exactly one terminal event.** | A session produces `EventHandshakeFailed` **or** `EventDisconnected`, once. A transport dying after a refused handshake adds nothing. |
| **Probe on silence.** | A probe goes out only after the silence window closes, once per cycle, and any valid frame — data, probe, ack, handshake — counts as life. On a busy connection no heartbeat frame is ever produced. |

## Wire format

Fixed, and identical in every Fomoxa implementation (implementation guide §2).
All multi-byte numbers are little-endian.

```
  type 0  DATA       [00]['C']['Y'][message id u32][length u32][payload]   11 + length
  type 1  PROBE      [01]                                                  1 byte, no body
  type 2  ACK        [02]                                                  1 byte, no body
  type 3  HANDSHAKE  [03][length u32][payload]                             5 + length
```

Caps: 16 MiB for a message payload, 1 MiB for a handshake payload, 1 000 000
messages in a hello.

On a byte-stream transport frames run back to back and any violation is fatal —
the decoder is poisoned and returns the same error forever, because there is no
point in a stream at which framing can be picked up again. On a packet transport
one packet holds exactly one frame, and a violation costs that packet only. The
asymmetry is deliberate, and both halves are tested.

## Transports

TCP and UDP ship here. Anything else — TLS, WebSocket, QUIC — belongs in its own
package that implements `Transport` and is handed to `NewConn`; adding one must
never require touching this package.

```go
type Transport interface {
    Kind() Kind
    Send(b []byte) Status
    Receive(buf []byte) (n int, need int, status Status)
    CloseSend()
    Close()
}
```

Four functions, and six answers to give: `StatusOK`, `StatusPending`,
`StatusClosed`, `StatusError`, `StatusTooLarge` (this frame will never fit — do
not retry it, and do not kill the session), `StatusTooSmall` (the buffer is too
small; `need` bytes are required and **the packet must be kept**).

`StatusPending` means *try again later and it will work*. Returning it for a
frame that is too large would have the core retry forever, which is why
`StatusTooLarge` exists as its own answer.

A stream transport returns whatever bytes it has, in any quantity; the framing
layer inside this package reassembles them. A packet transport returns exactly
one whole packet or `StatusPending` — never a partial one. Declare which you are
with `Kind()` and the branch is taken once, at construction.

Hand a transport to `NewConn` for the side that sends the hello, or to
`NewPeerConn` for the side that judges it. Both return the same `*Conn` with the
same `Tick`, `Send` and `Close`, so a package that adds a transport can offer its
own `Dial`/`Listen` helpers and never touch anything in here — which is the point
of the layering, and the test for whether a change belongs in this package at all.

The TCP and UDP transports are built on `syscall.RawConn` and are compiled for
unix platforms; on other platforms `DialTCP`, `DialUDP`, `ListenTCP` and
`ListenUDP` return `ErrUnsupported`, while everything else in the package —
framing, handshake, session, `Conn`, `Server`, and any transport you write — is
portable.

## Events

| Event | Raised when |
|---|---|
| `EventConnected` | The first tick of a session, always, on every transport |
| `EventReady` | Verdict 0 arrived (client), or was sent (server peer) |
| `EventHandshakeFailed` | Verdict 1, 2 or 3, a malformed verdict, or the client's handshake deadline |
| `EventMessage` | A data frame arrived while ready |
| `EventProbe` | A probe arrived while ready; the ack was already sent |
| `EventAck` | An ack arrived while ready |
| `EventDisconnected` | The transport reported closed or failed, or the peer stopped answering |

`Event.Verdict` carries meaning only on `EventHandshakeFailed`, where it is the
byte the server sent — and that byte *is* the reason, there is no second table to
look it up in. `Event.Err` is set on both terminal events and says what happened
in words.

`Event.Payload` is a copy, owned by you, and stays valid for as long as you hold
it. Other Fomoxa SDKs hand out a borrowed view valid only until the next tick;
this one does not, and code ported from them does not need the defensive copy.

## Timings

| Parameter | Default | Meaning |
|---|---|---|
| `HandshakeTimeout` | 5s | Client: the deadline for the whole handshake, query round included, never reset. Server: the silence window for a peer that has not finished handshaking |
| `HeartbeatInterval` | 5s | How long silence lasts before one probe goes out |
| `HeartbeatTimeout` | 15s | How long an unanswered probe waits before the peer is declared dead |

Worst-case death detection while ready is `HeartbeatInterval + HeartbeatTimeout`.
The server has no absolute handshake deadline: a peer that keeps answering probes
holds its slot indefinitely, which is the specified behaviour and not something
an implementation may tighten on its own.

## Tests

```
go test ./...
```

The suite follows the implementation guide's §11 checklist: byte-exact framing,
a stream decoded one byte at a time, all four branches of the server's
fingerprint gate, the query round and every way it can be malformed, heartbeat
cycles driven entirely by a fake clock, a transport that only ever answers
`StatusPending`, budget limits, and live TCP and UDP loopback sessions in both
directions.
